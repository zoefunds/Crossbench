## Trust boundary result

All protocol state transitions, deadline checks, party authorization, evidence
immutability, verdict production, settlement accounting, credits, and GEN
withdrawals are enforced by `contracts/crossbench_contract.py`.

The backend has no contract write client and no private key. Its GenLayer
adapter exposes only `readContract`; its mutations are limited to SIWE
application data and a disposable PostgreSQL mirror of contract views. Cache
contents cannot affect contract state, validator selection, evidence fetching,
verdicts, payouts, deadlines, or withdrawals.

## Findings fixed

- Post-write UI success was made strictly `FINALIZED`-gated. `ACCEPTED` is
  informational only and cannot trigger a state refresh or successful action.
- A finalized write now forces a live contract detail read, bypassing the
  backend's short read throttle. Fresh list loads drain every new contract page,
  not only the first 24 records.
- Response, evidence, and challenge deadlines now show live one-second
  countdowns on list, profile, and detail views. Buttons are locally disabled
  when a window closes, while contract timestamp checks remain authoritative.
- Successfully finalized actions are immediately disabled in component state to
  prevent repeat clicks while the live contract refresh completes.
- The claimant's contract-enforced pre-acceptance cancellation/refund path is
  now exposed in the frontend and finality-gated like every other write.
- Every evidence kind must now use a public HTTPS source. `ONCHAIN_REF` means an
  independently fetchable explorer/API URL; opaque references are rejected.
- Frontend evidence validation and placeholders now match that contract rule,
  preventing opaque or non-HTTPS sources from reaching wallet submission.
- Every validator executes the same evidence-fetch-and-assess function itself.
  The backend supplies no evidence content, prompt, score, or verdict.
- Cross-machine index polling now uses a PostgreSQL advisory lock; forced
  post-finality refreshes wait for the lock while scheduled duplicate polls skip.
- PostgreSQL RPC budgeting and endpoint rate limiting now increment atomically.
- Refresh sessions rotate through one consume-and-replace statement, preventing
  concurrent replay; short-lived access tokens refresh before expiry.
- Startup fails closed when contract, chain, origin, database, or secret settings
  are absent or malformed. Expired sessions/nonces/counters and old operations
  are cleaned on a coordinated hourly job.
- Operational failures are persisted for protected inspection, including indexer
  failures and RPC-budget exhaustion.
- Unused account-link functionality and its routes, UI, configuration, and table
  were removed completely.
- Ten backend and seven frontend automated tests cover finality gating, failed
  finalized receipts, forced live refresh, countdown expiry, token refresh timing,
  atomic refresh-cookie rotation, credentialed Vercel-to-Fly CORS, atomic RPC
  budgeting, cross-machine polling locks, indexer persistence, operational
  telemetry, and fail-fast configuration.
- Accepted transactions that remain unfinalized for two minutes and finalized
  validator/execution failures now emit rate-limited operational events containing
  only the transaction hash and contract action; telemetry cannot affect contract
  state or validator behavior.
- Frontend and backend npm advisory checks both complete successfully with zero
  vulnerabilities.
- RPC-budget exhaustion now emits the same persisted operational event whether
  production uses PostgreSQL or Upstash Redis, and scheduled cleanup failures
  are persisted rather than only printed. The verified backend image
  `deployment-01M45665XWTWC0N8JM5034PW9M` is live on both Fly machines with
  passing health checks.
- The production SIWE flow was exercised against Fly with the canonical Vercel
  origin: nonce, signature verification, and refresh all returned HTTP 200;
  credentialed CORS echoed only the canonical origin; the refresh cookie was
  `HttpOnly`, `Secure`, `SameSite=None`, scoped to `/auth`, and rotated on use.
- All project-authored documentation was reconciled against the deployed source
  and production configuration. Superseded Cloudflare/D1 instructions, retired
  contract addresses and aliases, incorrect wagmi/session descriptions, and
  misleading autofill language were removed. `MEMORY.md` now contains only the
  current operational handoff; Git history remains the historical record.

## External live-network check

The exact contract passes all 18 direct-mode tests. StudioNet's public RPC caused
DNS/TLS record-layer failures from Python, so the official test harness was routed
through a localhost-only Node JSON-RPC relay while retaining the real StudioNet
endpoint and validators. The exact production source then completed deployment,
creation, counter-stake, evidence submission, independent validator web fetch,
exact support/relevance agreement, and a preliminary verdict in 92.88 seconds.

The durable run is recorded in `docs/LIVE_LIFECYCLE_STATE.json`. Its real 48-hour
challenge window closes at `2026-10-07T04:22:26Z`; the idempotent `deadline` test
will resume that same contract to finalize, settle, withdraw the claimant refund,
and verify balanced accounting. The window is intentionally not shortened or
bypassed for testing.

A second durable lifecycle now targets the actual production contract configured
in both the backend and frontend. It created `ec-1`, counter-staked it, pinned both
evidence bundles, completed real validator consensus in 76.66 seconds, and reached
a `CLAIMANT` preliminary verdict. A forced production index refresh returned the
record and live assessment, and `https://crossbench-app.vercel.app/disputes/ec-1`
returned HTTP 200. Its state is recorded in
`docs/PRODUCTION_LIVE_LIFECYCLE_STATE.json`; the real challenge window closes at
`2026-10-07T04:42:50Z`. The deadline test resumes both durable runs, settles them,
withdraws every non-zero party credit with the correct wallet, and checks balanced
accounting.
- Validator agreement is exact on both `supports` and payout-critical
  `relevance`. Free-text explanation remains non-decision-critical.
- Unreachable sources are deterministically forced to `NEITHER`/`LOW`.
- Duplicate/incomplete assessment item sets are rejected.
- Verdict aggregation no longer uses floating-point arithmetic.
- Preliminary inconclusive results no longer increment the finalized
  inconclusive counter, fixing double-counted protocol statistics.
- Evidence URL validation now rejects credentials and private, loopback,
  link-local, reserved, and unspecified IPv4/IPv6 literal targets.
