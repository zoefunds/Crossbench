## Network-failure recovery disposition

StudioNet rolls back state when the outer consensus transaction fails. As a
result, a failure counter increment performed immediately before raising does
not persist on that network. Version 0.3.1 catches inner failures in direct-VM
tests, but its first real post-cutover assessment still left `eval_attempts=0`;
the outer failure bypassed the catch. The production contract at
`0x2352A0cBF175F1e69eBc8364A35301570378FF22` remains balanced and is routed
through both application services, but a deterministic two-phase attempt record
is still required for a network-reliable escape hatch. `docs/ESCROW_RECOVERY.md`
continues to describe the immutable historical deployments whose old code
cannot reach the threshold.
